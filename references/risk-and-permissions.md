# 风险与权限协议

## 何时读取

创建任务卡、准备修改文件、执行 Git、访问外部服务或进入人工 Gate 前读取。

## 风险分级

| 风险 | 典型内容 | 默认权限 |
| --- | --- | --- |
| R1 | 文档、模板、只读分析、独立样式、小测试 | 可自动执行并记录证据 |
| R2 | 边界清晰的业务逻辑、内部 API、局部 UI | 已批准任务内可自动修改，必须测试与 Review |
| R3 | 数据库、认证授权、公共 API、核心依赖、部署配置 | 修改前和合并前人工批准 |
| R4 | 生产数据、密钥、支付、不可逆迁移、生产发布 | 只分析和准备，不自主执行 |

风险不确定时按更高一级处理。把大任务拆小不能规避其真实风险。

## 自动允许

- 读取项目文件、规则、Git 状态和测试结果。
- 在已确认范围内创建文档、测试和 R1/R2 修改。
- 运行项目已有的非破坏性测试、Lint、类型检查和构建。
- 创建本 Skill 自己的本地功能分支或 worktree。
- 验证通过后创建只包含当前任务的本地提交。
- 用户配置已开启时，推送本 Skill 创建的分支并创建或更新 Draft PR。

## 必须人工批准

- LEVEL、范围、架构、数据库、公共 API 和安全策略。
- 初始化 Git、安装或升级核心依赖、访问生产和写入外部账号。
- 修改他人分支、公开评论、转为 Ready、合并、Release 和删除远程分支。
- 公开产品、价格、用户数据、商业承诺或宣传内容。

## 禁止

- Force Push 或改写公共历史。
- 自动 Stash、Reset、清理或提交用户无关修改。
- 把密钥、Token、日志、备份、真实用户数据和构建产物提交到仓库。
- 为通过测试而删除测试、降低断言或隐藏失败。
- 绕过平台权限、验证码、安全机制和分支保护。

## 公开包默认配置

```json
{
  "allow_push_own_branch": false,
  "allow_create_draft_pr": false
}
```

启用远程权限只适用于本 Skill 创建的分支。授权不会扩展到主分支、他人分支、Merge 或 Release。
