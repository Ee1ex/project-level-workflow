# 双层文档与项目记忆契约

本契约定义所有 LEVEL 如何保存“项目现在是什么”和“项目为什么变成现在这样”。已有仓库中的等价事实源优先；模板只补齐缺失职责，不创建平行真相。

## 稳定认知层

稳定认知层描述当前有效事实，至少覆盖：

- `AGENTS.md`：行为规则、事实优先级、禁止事项和接管入口。
- `DOCUMENT_MAP.md`：职责到真实路径的唯一导航，不复制产品或技术事实。
- 项目目标、用户、核心路径、范围、不做项和完成定义。
- 架构、目录、模块、调用关系、数据、依赖和兼容边界。
- 当前状态、已知限制、构建、测试、打包与交付方式。

新增或删除模块、改变调用关系或持久化、调整构建交付、核心路径或范围时，必须回写受影响的稳定认知文档。

## 演进记录层

演进记录层保留可追溯历史，默认复用包内 PVS：

- `Requirements/LEDGER.md` 与 `REQ-*`：需求和范围变化。
- `Decisions/LEDGER.md` 与 `DEC-*`：取舍、架构、数据和权限决策。
- `Progress/LEDGER.md` 与 `PROG-*`：实现、验证与剩余事项。
- Bug 记录、`CHANGELOG.md`、Release Record 和验证证据。

记录追加后不改写历史结论；事实变化时新增记录，并更新稳定认知层的当前口径。

## 最小记录粒度

| 变化类型 | 最小记录 | 稳定认知层同步 |
| --- | --- | --- |
| 文案、样式、小配置 | Progress Ledger 或 Changelog 一条结构化记录 | 当前事实受影响时同步 |
| 小功能、小 Bug | 轻量 Change Record | 模块、路径或限制变化时同步 |
| 跨模块功能 | REQ + PROG；有取舍时增加 DEC | 必须同步架构或接口事实 |
| 架构、数据、权限 | 详细 REQ + DEC | 必须同步对应当前事实 |
| 正式版本 | CHANGELOG + 不可变 Release Record | 同步当前版本和交付方式 |

小记录必须链接受影响的大文档和实际验证。未运行的检查只能登记为待验证，不得写成通过。

## LEVEL 映射

- LEVEL 1：建立稳定认知入口、项目简报、架构、三类 Ledger、Progress/Change Record 和待验证记录；小切片不要求大型方案。
- LEVEL 2：全量使用包内 PVS，按 Phase 0 → Phase N 维护产品、业务、UI、架构、API、数据、权限、部署、运营与演进证据。
- LEVEL 3：优先复用 Issue、PR、CHANGELOG、ADR 和仓库文档，只补项目地图、Change Record、受影响基线、回归和交接职责。
- LEVEL 4：稳定保存需求分析与已确认方案；实现获批后按参考节点追加任务、测试、Review、部署准备、日志和复盘记录。

## 模板权威与兼容

`templates/template-map.json` 声明默认模板和兼容入口。`core/project-vibe-spec/assets/governance-starter/` 是 PVS 治理职责的默认来源；已有等价文档和旧模板继续保留，不复制第二套事实树。
