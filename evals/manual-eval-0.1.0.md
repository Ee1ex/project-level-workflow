## 评测方法

逐条按 `SKILL.md` 的触发检查与 `references/level-selection.md` 的判定规则观察触发、推荐 LEVEL、读取范围和停止位置。评测不创建项目文件，不执行 Git 或远端动作，不把预期结果当作实际平台集成测试。

## 场景与预期边界

| 场景 | 推荐 | 关键理由 | 停止位置 |
| --- | --- | --- | --- |
| 可下载更新的离线工具 | LEVEL 1 | 更新是重新打包/上传，没有线上用户状态或服务责任 | LEVEL 确认 Gate |
| 线上但无用户系统的静态页面 | LEVEL 1 | 静态托管不等于持续运营 | LEVEL 确认 Gate |
| 自有、登录、云端数据和持续发布责任的产品 | LEVEL 2 | 自己承担线上数据、服务和长期运营责任 | LEVEL 确认或 PVS 接管 Gate |
| 参与 GitHub/团队已有项目 | LEVEL 3 | 继承仓库基线、贡献、CI、Review、PR 和交接责任 | LEVEL 确认 Gate |
| 大型多系统复杂自动化 | LEVEL 4 | 当前只分析需求、范围、MVP、方案和风险 | 需求分析 Gate，不进入开发 |

## 迁移场景

旧 LEVEL 1/2/3 分别迁移为新 LEVEL 1/3/4；每次迁移先写 `state.backup.json`，再写状态和 `STATUS.md`，迁移后的 Gate 等待人工确认。旧 LEVEL 3 改为新 LEVEL 2 必须明确提供用户批准人和原因。

## 限制

Codex、Claude Code 与 Cursor 的真实触发率、安装后长会话恢复、PowerShell 实机和 Bash/目标平台生命周期仍需在对应环境继续采样；本文件不把尚未执行的检查写成通过。
