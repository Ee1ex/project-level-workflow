## 安全默认值

- `allow_push_own_branch=false`。
- `allow_create_draft_pr=false`。
- `git init` 必须先通过人工 Gate。
- 本地提交只允许 Skill 创建或明确接管的分支、当前任务范围内文件和完整通过的验证证据。
- 默认分支直推、删除远端分支、转 Ready、Merge、Release 不自动执行。
- Force Push 与改写公共历史禁止执行。
- 生产部署、公开宣传发布和外部账号高影响写入必须人工确认。
- Qima 仅提醒用户按需手动考虑，不直接调用。

## 更新与回滚

更新应从新下载并审查的 Release 目录运行。更新器先执行 Doctor；项目级更新发现状态文件时先执行 Schema 迁移，再把旧 Skill 移动到带时间戳的 `backup` 目录并写入新版本。

回滚时停止 Agent 执行，将当前安装目录移出托管路径，再把对应 `backup` 目录恢复为 `project-level-workflow`。项目中的 `.project-workflow/` 与 `docs/project-workflow/` 默认保留；状态迁移前的 `state.backup.json` 可用于人工恢复。恢复后重新运行 Doctor 和状态校验。

## 已知限制

- 首版只提供中文用户文档和错误消息。
- 三个平台的实际触发质量仍需安装后持续收集误触发与漏触发样本。
- Bash 生命周期只通过静态合同，尚无当前环境的语法或实机证据。
- Product Design、Supabase、GitHub、Vercel、Netlify 等外部能力按需路由，不随本包安装；使用前仍要确认可用性、登录、权限和技术栈匹配。
- 生命周期脚本不自行从网络下载代码；用户需先审查 Clone 或 Release 内容，再本地执行。

## Git 初始化提案

- 目标目录：当前项目根目录。
- 默认分支：`main`。
- 建议仓库名：`project-level-workflow`。
- 首次提交信息：`feat: add project level workflow skill`。
- 首次提交范围：三份 SOP、Skill、README、版本与许可证、references、templates、schemas、scripts、adapters、evals、tests、发布与设计文档。
- 排除范围：`__pycache__/`、`*.pyc`、本地环境文件、密钥、临时目录和项目外文件。

项目维护者已批准 Git 初始化，本报告与上述发布范围将纳入 `main` 的首次本地提交。GitHub 仓库可见性、Remote、Push、Tag 与 Release 仍是后续独立 Gate。
